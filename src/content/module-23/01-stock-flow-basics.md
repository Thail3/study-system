อ่างอาบน้ำใบหนึ่ง มีก๊อกน้ำเปิดไหลเข้า มีท่อระบายให้น้ำไหลออก ระดับน้ำในอ่าง ณ เวลาใดเวลาหนึ่ง — นั่นแหละคือตัวอย่างที่ใช้สอน Systems Thinking กันมาหลายสิบปี เพราะมันมีองค์ประกอบครบทุกอย่างที่ต้องเข้าใจก่อนจะไปเรียนเรื่องซับซ้อนกว่านี้: มีสิ่งที่ **สะสม** อยู่ (น้ำในอ่าง) และมีสิ่งที่ทำให้สิ่งนั้น**เปลี่ยนแปลง**ไปตามเวลา (น้ำไหลเข้า/ไหลออก)

## Stock คืออะไร

**Stock** คือปริมาณสะสม ณ ช่วงเวลาหนึ่ง — สิ่งที่คุณ "วัดได้" ถ้าหยุดเวลาแล้วมองดูตอนนั้นเดี๋ยวนั้น เช่น ระดับน้ำในอ่าง (วัดได้ทันทีว่ากี่ลิตร), เงินในบัญชีธนาคาร (วัดได้ทันทีว่ากี่บาท), จำนวนพนักงานในบริษัท (นับได้ทันทีว่ากี่คน) — สังเกตว่า stock ตอบคำถาม **"ตอนนี้มีเท่าไหร่"** เสมอ

## Flow คืออะไร

**Flow** คืออัตราการเปลี่ยนแปลงของ stock ต่อหน่วยเวลา — สิ่งที่คุณวัดไม่ได้จากการหยุดเวลาดูครั้งเดียว ต้องดูสองช่วงเวลาเปรียบเทียบกันถึงจะรู้ เช่น น้ำไหลเข้ากี่ลิตรต่อนาที (inflow), เงินเดือนที่โอนเข้าบัญชีกี่บาทต่อเดือน (inflow), พนักงานลาออกกี่คนต่อเดือน (outflow) — flow ตอบคำถาม **"เปลี่ยนแปลงเร็วแค่ไหน"** ไม่ใช่ "ตอนนี้มีเท่าไหร่"

ความสัมพันธ์ระหว่างสองอย่างนี้ตรงไปตรงมา: **stock ที่เวลา t+1 = stock ที่เวลา t + inflow − outflow** สูตรง่ายๆ นี้คือแกนของทุกอย่างในโมดูลนี้และโมดูลถัดไปทั้งหมด

สัญลักษณ์ก้อนเมฆในแผนภาพ (cloud) มีความหมายเฉพาะ — มันคือ "แหล่งที่มา/ปลายทางที่อยู่นอกขอบเขตระบบที่เรากำลังวิเคราะห์" เราไม่สนใจว่าน้ำมาจากท่อประปาเส้นไหน หรือน้ำที่ระบายออกไปจะไหลไปที่ท่อระบายน้ำสาธารณะแบบไหนต่อ — สำหรับขอบเขตการวิเคราะห์นี้ ถือว่ามัน "ไม่จำกัด" (infinite source/sink) นี่คือทักษะสำคัญอีกอย่างของ Systems Thinking: การตัดสินใจว่าจะวาด**ขอบเขตของระบบ** (system boundary) ตรงไหน — เรื่องนี้จะกลับมาเจออีกครั้งแบบลึกในโมดูล System Traps & Mental Models

## ลองเล่นเอง: ปรับ inflow/outflow แล้วดู stock

```demo

caption: ลองปรับ inflow rate กับ outflow rate ดูว่า stock (ระดับน้ำ) วิ่งไปทางไหน
```

สังเกตพฤติกรรมสามแบบที่เกิดขึ้นได้จากโครงสร้างง่ายๆ นี้:

- **inflow > outflow** → stock เพิ่มขึ้นเรื่อยๆ (น้ำล้นอ่างถ้าปล่อยไว้นานพอ)
- **inflow < outflow** → stock ลดลงเรื่อยๆ (อ่างแห้งในที่สุด)
- **inflow = outflow** → stock คงที่ — นี่คือสภาวะที่เรียกว่า **equilibrium** หรือ **steady state**

จุดที่มักถูกเข้าใจผิดคือ "stock คงที่" **ไม่ได้แปลว่าไม่มีอะไรเกิดขึ้น** — น้ำยังไหลเข้าไหลออกตลอดเวลา (flow ไม่ใช่ศูนย์) แค่บังเอิญเท่ากันพอดี ระบบที่ steady state จากภายนอกดูเหมือนนิ่งสงบ แต่ภายในอาจมี flow ที่วิ่งแรงมากทั้งสองทาง — เหมือนบริษัทที่จำนวนพนักงานคงที่ 200 คนมา 3 ปีติด อาจดูมั่นคง แต่ถ้า turnover สูงมาก (รับเข้า 80 คน/ปี ลาออก 80 คน/ปี) นั่นคือบริษัทที่กำลังมีปัญหาหนักซ่อนอยู่ ต่างจากบริษัทที่คงที่ 200 คนเพราะแทบไม่มีใครเข้าใครออกเลย ทั้งที่ stock เท่ากันเป๊ะ

## ทำไม Stock ถึงเป็นตัวแปรที่สำคัญที่สุดในการตัดสินใจ

Stock มีคุณสมบัติพิเศษที่ flow ไม่มี — มันมี**ความเฉื่อย** (inertia) เปลี่ยนแปลงทันทีไม่ได้ ต้องสะสมผ่าน flow ไปเรื่อยๆ นี่คือเหตุผลที่การตัดสินใจในระบบจริงมักช้ากว่าที่คนคาดหวัง — บริษัทที่อยากลดหนี้ (stock) ลงครึ่งหนึ่ง ทำไม่ได้ในวันเดียวต่อให้หยุดกู้เพิ่มทันที (ปิด inflow) เพราะต้องรอ outflow (การจ่ายคืน) ค่อยๆ ลดสะสมลงตามเวลา

| ระบบ | Stock (สะสม, วัดได้ทันที) | Inflow | Outflow |
|---|---|---|---|
| ธนาคาร | เงินในบัญชี | เงินเดือนเข้า, ดอกเบี้ย | ค่าใช้จ่าย, ถอนเงิน |
| ทีมวิศวกร | จำนวนพนักงาน | จ้างใหม่ | ลาออก/ถูกเลิกจ้าง |
| ระบบ web server | จำนวน request ที่ค้างอยู่ในคิว | request เข้าใหม่ | request ที่ประมวลผลเสร็จ |
| โปรเจกต์ซอฟต์แวร์ | Technical debt สะสม | ทางลัดที่ทีมเลือกใช้ | เวลาที่ทีมใช้ refactor คืน |

โมดูลถัดไปในหัวข้อนี้จะพาไปดู stock ที่ซ่อนอยู่ในโลกซอฟต์แวร์และองค์กรแบบเจาะลึกกว่านี้ ก่อนจะไปเจอ **delay** ซึ่งเป็นตัวแปรที่ทำให้ stock/flow ที่ดูง่ายๆ แบบนี้ กลายเป็นเรื่องที่ทำนายพฤติกรรมได้ยากขึ้นมากในหัวข้อสุดท้ายของโมดูลนี้
