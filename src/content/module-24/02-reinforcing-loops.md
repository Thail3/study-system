เงินฝากธนาคาร 100,000 บาท ดอกเบี้ยทบต้น 10% ต่อปี ปีแรกได้ดอกเบี้ย 10,000 บาท ปีที่สองฐานเงินต้นกลายเป็น 110,000 บาท ได้ดอกเบี้ย 11,000 บาท ปีที่สามฐานเป็น 121,000 บาท ได้ดอกเบี้ย 12,100 บาท — ตัวเลขที่เพิ่มขึ้นแต่ละปีไม่เท่ากัน แต่**เพิ่มขึ้นเรื่อยๆ ไม่มีเพดาน** นี่คือลายเซ็นของ **Reinforcing Loop** วงจรที่ผลลัพธ์ของมันย้อนกลับไปขยายสาเหตุตั้งต้นให้แรงขึ้นอีก แรงขึ้นอีก ไม่มีจุดหยุดในตัวมันเอง

## โครงสร้างของ Reinforcing Loop

Reinforcing Loop (เขียนย่อว่า **R**) ต่างจาก Balancing Loop ตรงที่**ไม่มีลิงก์ลบเลย หรือมีลิงก์ลบเป็นจำนวนคู่** — ผลคือทุกครั้งที่วนครบหนึ่งรอบ ค่าที่ได้จะขยายไปในทิศทางเดิมเสมอ ไม่ใช่ถูกหักล้าง

ตัวอย่างที่วิศวกรซอฟต์แวร์เจอบ่อยแต่มักไม่รู้ว่ามันคือ R loop: **Tech Debt Spiral**

ทุกลิงก์ในวงนี้เป็น **"+"** — debt เพิ่ม → ทีมช้าลง (จริง เพราะโค้ดยุ่งเหยิงแก้ยากขึ้น) → ทีมช้าลง → ทางลัดเพิ่ม (จริง เพราะโดนกดดันเรื่องเวลามากขึ้น) → ทางลัดเพิ่ม → debt เพิ่ม (จริง) วนกลับไปจุดเริ่มต้นด้วยค่าที่**มากกว่าเดิม** นี่คือเหตุผลที่ทีมที่ปล่อย tech debt ไว้นานๆ โดยไม่มี balancing loop (เช่น เวลา refactor ที่จัดสรรไว้แน่นอน) มักเจอความเร็วที่ลดฮวบแบบทวีคูณ ไม่ใช่ลดแบบเส้นตรง

## R Loop ไม่ได้แปลว่าแย่เสมอไป

ข้อควรระวังคือคนมักเข้าใจผิดว่า reinforcing loop คือของไม่ดี — จริงๆ แล้ว R loop เป็นกลไกเบื้องหลัง**การเติบโตที่ดี**พอๆ กับความหายนะ:

- **Viral growth** — ผู้ใช้บอกต่อ → ผู้ใช้ใหม่เพิ่ม → มีคนบอกต่อมากขึ้น → ผู้ใช้ใหม่เพิ่มขึ้นอีก (R loop ที่ธุรกิจทุกแห่งอยากได้)
- **Compound learning ของทีม** — ทีมมี documentation ดี → onboarding คนใหม่เร็ว → มีเวลาไปเขียน documentation เพิ่ม → onboarding เร็วขึ้นอีก
- **Flywheel ของ Amazon** — ราคาถูกลง → ลูกค้าเยอะขึ้น → seller เยอะขึ้น → selection เยอะขึ้น → ลูกค้าเยอะขึ้นอีก → cost structure ดีขึ้น → ราคาถูกลงอีก

จุดสำคัญคือ **R loop ไม่มีเป้าหมายในตัวมันเอง** ไม่ว่าจะเป็นทิศบวกหรือลบ มันจะขยายตัวต่อไปเรื่อยๆ จนกว่าจะมี**อย่างอื่น**มาหยุดมัน (ทรัพยากรหมด ตลาดอิ่มตัว หรือ balancing loop อื่นเข้ามาคาน) — R loop ที่ดีจึงต้องถูกออกแบบร่วมกับการรู้ล่วงหน้าว่าอะไรจะมาเป็นเพดานตามธรรมชาติ ไม่งั้นมันจะพุ่งชนกำแพงแบบไม่ทันตั้งตัว (เรื่องนี้คือแก่นของโมดูล Behavior Patterns หัวข้อ "Overshoot and Collapse" ที่จะเจอถัดไป)

## ลองเล่นเอง: เห็นความต่างระหว่าง R กับ B

```demo
component: FeedbackLoopSimulator
caption: สลับดู R (พุ่งไม่หยุด) กับ B (ไล่เข้าเป้าหมายแล้วนิ่ง) จากสมการง่ายๆ ตัวเดียวกัน ต่างกันแค่ทิศของ feedback
```

สังเกตว่าโค้ดที่ขับเคลื่อนทั้งสองแบบต่างกันนิดเดียว — R loop คือ "ค่าใหม่ = ค่าเดิม + ค่าเดิม × strength" (ยิ่งค่าเดิมสูง ยิ่งเพิ่มแรง) ส่วน B loop คือ "ค่าใหม่ = ค่าเดิม + (เป้าหมาย − ค่าเดิม) × strength" (ยิ่งใกล้เป้าหมาย ยิ่งเพิ่มช้าลง) — ความต่างเล็กๆ ในสมการนี้ผลิตพฤติกรรมที่ต่างกันโดยสิ้นเชิงในระยะยาว นี่คือตัวอย่างที่ชัดเจนที่สุดของหลักการ "structure produces behavior" ที่เรียนมาในโมดูลแรก

## เปรียบเทียบสรุป

| แง่มุม | Balancing Loop (B) | Reinforcing Loop (R) |
|---|---|---|
| จำนวนลิงก์ "−" ในวง | เลขคี่ | เลขคู่ (รวมศูนย์) |
| มีเป้าหมายไหม | มี — ดึงเข้าเป้าหมาย | ไม่มี — ขยายตัวไปเรื่อยๆ |
| พฤติกรรมระยะยาว (ไม่มีอะไรมาแทรก) | เข้าใกล้ค่าคงที่ (หรือแกว่งถ้าแรง/delay เยอะ) | โตแบบทวีคูณ (หรือดิ่งแบบทวีคูณถ้าทิศเป็นลบ) |
| ตัวอย่างซอฟต์แวร์ | rate limiter, circuit breaker, autoscaling | viral growth, tech debt spiral, cache thrashing |

โมดูลถัดไปในหัวข้อนี้จะสอนวิธี**อ่าน** causal loop diagram อย่างเป็นระบบ — วิธีนับลิงก์ลบเพื่อบอกว่าวงไหนคือ R วงไหนคือ B แม้แต่ในไดอะแกรมที่ซับซ้อนกว่าที่เห็นมาสองหัวข้อนี้มาก
