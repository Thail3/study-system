บริษัทมีสองโปรเจกต์ภายในที่แข่งกันแย่ง headcount จากพูลกลางเดียวกัน ไตรมาสแรก Project A บังเอิญมีผลงานดีกว่านิดหน่อย ผู้บริหารเลยจัดสรร headcount เพิ่มให้ A มากกว่า B ตามหลัก "ให้รางวัลกับผลงานที่ดี" — พอ A มีคนเพิ่ม ผลงานยิ่งดีขึ้นไปอีก ได้ headcount เพิ่มอีกในไตรมาสถัดไป ส่วน B ที่เหลือคนน้อยลง ผลงานยิ่งแย่ลง ยิ่งได้ headcount น้อยลงอีก ผ่านไปสองปี A กลายเป็นโปรเจกต์หลักที่รุ่งเรือง ส่วน B ถูกยุบทิ้งไปเงียบๆ — ทั้งที่ตอนเริ่มต้น ทั้งสองโปรเจกต์มีศักยภาพพอๆ กัน ต่างกันแค่ผลลัพธ์ไตรมาสแรกที่อาจจะเป็นแค่โชค

## Success to the Successful: ความได้เปรียบเล็กๆ ที่ขยายตัวเองผ่านกลไกจัดสรร

**Success to the Successful** เกิดขึ้นเมื่อสองฝ่ายแข่งกันแย่งทรัพยากรจำกัดชุดเดียวกัน โดยกลไกจัดสรรใช้ **ผลงานที่ผ่านมา** เป็นเกณฑ์ — ทำให้แต่ละฝ่ายมี R loop ของตัวเอง (ยิ่งได้ทรัพยากร ยิ่งมีผลงานดี ยิ่งได้ทรัพยากรเพิ่ม) แต่ทั้งสอง R loop นี้ **ผูกกันผ่านทรัพยากรที่มีจำกัด** — <mark class="hl-insight">พอฝ่ายหนึ่งโต อีกฝ่ายจึงหดตัวลงโดยอัตโนมัติ ไม่ใช่เพราะฝ่ายนั้นแย่กว่าจริงๆ แต่เพราะกลไกจัดสรรขยายความได้เปรียบเล็กๆ ในช่วงแรกให้กลายเป็นความได้เปรียบมหาศาลในระยะยาว</mark>

## ทำไมมันมักถูกมองว่า "ยุติธรรมดีแล้ว" ทั้งที่ผลลัพธ์บิดเบือน

จุดที่ทำให้ archetype นี้อันตรายเป็นพิเศษคือกลไกที่ขับเคลื่อนมันมักดู**สมเหตุสมผลและยุติธรรมในทุกขั้นตอน** — "ให้รางวัลกับผลงานดี" ฟังดูถูกต้องเสมอ ไม่มีใครในกระบวนการตั้งใจกีดกันฝ่ายที่แพ้เลย แต่<mark class="hl-warning">ผลสะสมในระยะยาวคือความเหลื่อมล้ำที่ขยายตัวเองไปเรื่อยๆ จนแทบเป็นไปไม่ได้ที่ฝ่ายเสียเปรียบจะไล่ทัน</mark> — ไม่ว่าฝ่ายนั้นจะมีศักยภาพจริงแค่ไหนก็ตาม เพราะไม่เคยได้รับทรัพยากรพอจะแสดงศักยภาพนั้นออกมาเลย

## ตัวอย่างที่พบบ่อย

| ทรัพยากรจำกัด | ฝ่ายที่ได้เปรียบตั้งแต่ต้น | ผลระยะยาว |
|---|---|---|
| Engineering headcount ระหว่างโปรเจกต์ | โปรเจกต์ที่มี metric ดีในไตรมาสแรก (อาจเพราะโชคหรือ market timing) | โปรเจกต์อื่นที่มีศักยภาพจริงแต่เริ่มช้ากว่า ไม่เคยได้โอกาสพิสูจน์ตัว |
| เวลา code review จาก senior engineer | Service/team ที่ senior คุ้นเคยอยู่แล้ว | Service ใหม่ได้ review ช้า คุณภาพต่ำกว่า ยิ่งไม่มีใครอยากไปแตะ |
| งบการตลาดตามยอดขายที่ผ่านมา | สินค้าที่ขายดีตั้งแต่เปิดตัว | สินค้าใหม่ที่ดีจริงแต่ยังไม่มี traction ไม่ได้งบพอจะสร้าง traction เลย |
| Traffic ที่ recommendation algorithm จัดสรรตาม engagement | Content/creator ที่ viral ตั้งแต่ต้น | Content คุณภาพดีแต่ไม่ viral ในช่วงแรก แทบไม่ถูกมองเห็นอีกเลย |

## ทางแก้: แยกเกณฑ์จัดสรรออกจากผลงานสะสม เป็นระยะๆ

ทางแก้ที่ใช้ได้จริงคือการ**ตั้งกลไกที่ไม่ผูกการจัดสรรเข้ากับผลงานสะสมแบบอัตโนมัติตลอดไป** เช่น กันงบ/headcount ส่วนหนึ่งไว้สำหรับโปรเจกต์ที่มีศักยภาพแต่ยังไม่มี traction โดยเฉพาะ (deliberately ring-fence), ประเมินผลงานเทียบกับทรัพยากรที่ได้รับ (ROI ต่อ headcount) แทนผลงานสัมบูรณ์, หรือหมุนเวียนโอกาส (rotation) ให้ทุกฝ่ายได้ resource ระดับหนึ่งเป็นระยะ ไม่ปล่อยให้กลไก "ยิ่งเก่งยิ่งได้" ทำงานแบบไม่มีการแทรกแซงเลยตลอดไป

หัวข้อสุดท้ายของโมดูลนี้จะพาไปดู archetype ที่รุนแรงที่สุดในกลุ่มนี้ — **Escalation** ซึ่งเกิดขึ้นเมื่อสองฝ่ายแข่งกันตอบโต้กันไปมา จนความรุนแรงของการแข่งขันพุ่งสูงเกินกว่าที่ทั้งสองฝ่ายตั้งใจไว้แต่แรกมาก
