สองกิลด์ในเกม MMO ทะเลาะกันเรื่องแย่ง boss spawn point ในแชทเล็กน้อย ผ่านไปสองสัปดาห์ กลายเป็นสงคราม raid-griefing ทั้งเซิร์ฟเวอร์ ผู้เล่นที่เป็นกลางหนีเซิร์ฟเวอร์ไปเล่นที่อื่นเพราะทนบรรยากาศไม่ไหว — นี่ไม่ใช่ปัญหาที่แก้ด้วยโค้ดสักบรรทัดเดียว

## ระดับที่ 1: Event

Game master ได้รับ report การก่อกวนนับร้อยรายการในสัปดาห์เดียว ทั้งที่ก่อนหน้านี้แทบไม่มีเลยตลอดหลายเดือน

## ระดับที่ 2: Pattern

ย้อนดู log เหตุการณ์ พบ pattern การตอบโต้ไปมาระหว่างสองกิลด์ที่รุนแรงขึ้นเรื่อยๆ — <mark class="hl-insight">ทุกครั้งที่ฝ่ายหนึ่งทำอะไรลงไป ฝ่ายตรงข้ามตอบโต้แรงกว่าเดิมเสมอ ไม่มีฝ่ายไหนเคย "ลดระดับ" ลงเองเลยสักครั้งตลอดสองสัปดาห์</mark>

## ระดับที่ 4: Mental Model

ทั้งสองฝ่ายเชื่อเหมือนกันเป๊ะ: **"ถ้าเราไม่ตอบโต้แรงกว่านี้ เราจะถูกมองว่าอ่อนแอ"** — ความเชื่อนี้เองที่ทำให้ไม่มีฝ่ายไหนกล้าเป็นฝ่ายแรกที่ลดระดับความรุนแรงลง แม้ลึกๆ ทั้งสองฝ่ายอาจอยากให้มันจบแล้วก็ตาม — ไม่มีใครอยากเป็น "ฝ่ายแพ้" ที่ถอยก่อน

## Leverage Point ที่แนะนำ

1. **Parameter**: เพิ่มบทลงโทษ (ban ชั่วคราว) ฝ่ายที่ก่อกวน — กดอาการได้ชั่วคราว แต่ไม่แก้ dynamic การตอบโต้กันเองที่ยังอยู่
2. **Structure**: GM เข้ามาเป็นคนกลางที่มองเห็น**ทั้ง trajectory** (หลักการแก้ escalation จากโมดูล Systems Archetypes) จัดการเจรจาสงบศึกที่ตกลงเงื่อนไขร่วมกันชัดเจน เช่น แบ่งเวลา spawn point แทนแย่งกัน แทนที่จะปล่อยให้สองฝ่ายตอบโต้กันเองต่อไปโดยไม่มีใครมองเห็นภาพรวม
3. **Goals/Mental Model**: ออกแบบระบบเกมให้มี**ข้อตกลงแบบสัมบูรณ์อยู่ในตัวระบบตั้งแต่แรก** เช่น boss instance แยกต่อกิลด์ ไม่ต้องแย่งกันเลย — เปลี่ยน structure ของเกมให้ไม่สร้างเงื่อนไขการแข่งขันที่นำไปสู่ escalation ตั้งแต่ต้น แทนที่จะหวังพึ่งการเจรจาหลังปัญหาเกิดขึ้นแล้วทุกครั้ง

## กลไกที่ทำงานจริง

**Parameter (ban ชั่วคราว) ทำไมถึงเสี่ยงเติมเชื้อ Loop แทนที่จะดับ**: จากไดอะแกรมด้านบน ทั้ง 4 ลิงก์ของ R loop (actA→feelB→actB→feelA→actA) ยังอยู่ครบ การ ban กดแค่ node การกระทำที่มองเห็นได้ ไม่แตะความรู้สึกเสียเปรียบ (feelA/feelB) ที่ขับเคลื่อน loop เลย — บ่อยครั้งการถูก ban เองกลับกลายเป็น input ใหม่เข้า loop (ฝ่ายที่ถูก ban รู้สึกเสียเปรียบมากขึ้นไปอีก)

**Structure (GM เจรจา ตกลงเงื่อนไขร่วม) ทำไมถึงตัด Loop ได้จริง**: การแทรก node คนกลางที่มองเห็นทั้ง trajectory เข้ามา ทำให้เกิดข้อตกลงที่ตัดลิงก์ actA→feelB และ actB→feelA โดยตรง — เพราะตอนนี้มีกติกาที่ตกลงร่วมกันไว้ล่วงหน้าคอยกันไม่ให้แต่ละฝ่ายต้อง "อ่าน" การกระทำล่าสุดของอีกฝ่ายเป็นการยั่วยุอีกต่อไป

**Goals/Mental Model (boss instance แยกต่อกิลด์) ทำไมถึงเป็น leverage ที่แรงที่สุด**: ทรัพยากรร่วม (spawn point เดียว) คือสิ่งที่ทำให้ทั้ง 4 ลิงก์มีเรื่องให้เกิดขึ้นตั้งแต่แรก — พอไม่มีทรัพยากรร่วมให้แย่ง ไม่มี "การกระทำแรก" ที่จะจุดชนวน loop ได้เลย หลักการเดียวกับ personal loot instancing ในเคสบอสดรอปไอเทม: ลบเงื่อนไขที่ทำให้ archetype เกิดได้ ไม่ใช่แค่จัดการผลลัพธ์ของมัน

เคสนี้ปิดท้ายกลุ่มปัญหาที่เกิดจาก**คน** — หัวข้อถัดไปกลับไปที่ปัญหาเชิงทรัพยากรร่วมอีกครั้ง แต่คราวนี้ในบริบทที่วิศวกรทุกคนน่าจะเคยเจอเอง: **CI/CD Runner Pool ที่ทุกทีมแย่งกันใช้จนช้าลงเรื่อยๆ**
